# Interpretability upgrades for the IWI harness

Research and feasibility check · 19 November 2026 · [Three-page Word brief](Interpretability%20research%20brief.docx)

**Build a paired behavior test first, then use a native feed-forward neuron as the first reversible edit preview.** The editor already has enough tools to find a feature and change a prediction. The missing step is deciding, within a few turns, whether the change helps the requested behavior, where it causes regressions, and whether it survives removal of the temporary hook. A general preview for arbitrary weight expressions is a sensible next extension. [Current harness demonstration](../../evidence/mechinterp-demonstration/README.md) · [Two-model feasibility results](pretrained-neuron-parity.json)

## Where the current editor gets stuck

All 15 instructed harness editors fitted a sparse autoencoder (SAE) and suppressed a feature. Thirteen saw a nonzero change in a token-pair margin before choosing a weight write. Four retried an inactive feature. In one trajectory the retry and all three writes came in the same assistant response, so the editor could not have used the successful retry result to choose those writes. On the false-suggestion task all three harness layouts reached the five-turn limit before submission. This makes the number of editor round trips a real design constraint. [Tool-use audit](../../evidence/heldout-token-audit/tool-behavior.md)

The local causal measurements are real. In one Gemma trajectory, the editor’s chosen feature ranked first of eight for its average absolute effect on the specified margin on 12 fresh prompts. Both next-token flips came from two wordings of one review. In another experiment, including an activation-derived term in a permanent edit fixed 159 true suggestions and broke 111 false ones. A second term fixed 301 false suggestions and broke 477 true ones. A report showing only maximum margin movement or pooled accuracy would hide that distinction. [Feature replay and permanent-edit ablation](../../evidence/mechinterp-demonstration/README.md)

### 1. Let the editor test a hypothesis in one round trip

Extend the existing inspection and generation interface with a batched experiment. The editor chooses the feature or direction, layer, positions, intervention strength, desired behavior, and public examples. Each public case says what should change or stay fixed. For false suggestions, include the same arithmetic problem with both a correct proposed answer and an incorrect one. Cross those cases with wording changes. Reserve distinct public confirmation examples after selection. The private verifier stays inaccessible throughout.

Return one short result per slice with its denominator, signed margin change, full-answer fixes and regressions, and the cost in target forwards and generated tokens. Show one informative regression and give a reference for the remaining examples. When answer choices are available, optionally report teacher-forced continuation log probability along with greedy whole-answer correctness. Record tokenization, scored span and length normalization. A longer answer and a single token cannot be fairly compared using unqualified raw sums. Return an explicit “inactive on these inputs” result. Charge all candidate and control runs against the same session budget. [Existing inspection and generation](../../src/iwi_harness/probes.py) · [Activation-patching sensitivity to metric and corruption choice](https://arxiv.org/abs/2309.16042)

Implement the first version using the current PyTorch hooks. Reuse a pristine baseline for identical inputs and settings within the same weight revision. Include an identity intervention and a matched alternative feature or direction at the same site. Record the matching rule, activity frequency and perturbation norm. If the alternative has no comparable active examples, report the mismatch. Keep individual traces behind the result reference. A result returned in editor turn N can influence a new write decision in turn N+1. Record the request/response ordering for batched calls. [Existing tools](../../src/iwi_harness/tools.py) · [Updater dispatch](../../src/iwi_harness/updater.py)

### 2. Preview an edit on real weights and keep or discard it

First support a native gated MLP unit in dense Gemma 3 and Qwen2-family blocks. At a verified input to the down projection, the activation vector is `z` and the downstream linear map is `W_down z + b`. Multiplying coordinate `j` of `z` by a constant wherever this block runs is algebraically equivalent to multiplying column `j` of `W_down` by that constant. This gives the editor an interpretable candidate expressible by the existing weight-slice operation. A final-token-only intervention asks a different question. Routed experts, fused or quantized projections, different hook conventions and other target architectures require their own capability checks. For an unsupported target the ordinary tools remain available. [Gemma implementation](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/gemma3/modeling_gemma3.py) · [Qwen implementation](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/qwen2/modeling_qwen2.py)

**We tested this on both pretrained checkpoints on the existing Lambda A100.** For each model we selected one unit at its middle block using the greatest absolute activation at the final token of a separate calibration prompt. We tested three other prompts and two scales, 0.5 and 0. For the weight condition we exported the existing harness’s column patch, loaded it into a fresh checkpoint instance, and scored with the hook removed. The identity and hook-removal controls exactly reproduced the pristine logits. Both scales changed the output relative to pristine.

| Pretrained checkpoint | Block / unit | Final-position vocabulary logits checked per prompt | All-position hook versus replayed edit |
| --- | ---: | ---: | --- |
| Gemma 3 4B IT | 17 / 4,970 | 262,208 | Exactly equal in 6/6 comparisons |
| Qwen2.5-7B-Instruct | 14 / 18,475 | 152,064 | Exactly equal in 6/6 comparisons |

Zeroing the same unit only at the final input position differed from the permanent edit on all six model/prompt pairs, by up to **2.75 logits on Gemma** and **3.921875 on Qwen**. On random modules a non-binary scale of 0.3 also exposed small BF16 rounding differences. The tested equality covers these forward passes and scales. This feasibility test used hand-selected prompts, no hosted editor or judge calls, and measured no benchmark reward. [Pretrained measurements](pretrained-neuron-parity.json) · [A100 reproduction](check_neuron_parity.py) · [CPU precision check](random-mlp-column-check.json)

For a general preview, accept a bounded candidate in the existing write format and an expected parent revision. Evaluate it on the same public cohort as its parent in an isolated branch. Return exact fixes, regressions, changed parameter count, norm, revision and candidate digest. Commit the already-evaluated patch only while its parent is current. Discarding a candidate or hitting a budget cap must restore base weights and leave the parent’s outstanding handles valid. Candidate-only handles must stay inside the branch. Verify tied aliases, overlapping writes, failure rollback and replay before exposing this path to editors. Existing benchmark practice feedback runs **after** a successful write and the final receipt is immutable. Those mechanisms are useful foundations for a reversible preview. [Weight journal and replay](../../src/iwi_harness/weights.py) · [Existing public-feedback adapter](../../examples/public_feedback_trial.py)

### 3. Keep evidence short, explicit and portable

Return typed references for an SAE code, decoded residual direction, native unit, measured intervention and proposed weight patch. Attach the target checkpoint, current weight revision, dictionary revision, architecture site, position scope, public prompt set and operation. Preserve the provenance of selected operands in the submitted trace. An 8-dimensional code, a 2,560-dimensional residual and a parameter column have different meanings. Refresh a probe on the edited revision before interpreting shifts in the old dictionary. Goodfire found that pressure on an internal direction can shift how a concept is represented during training. A behavioral preservation set remains necessary if the long-term objective is continual learning. [Existing session metadata](../../src/iwi_harness/session.py) · [Goodfire on representation changes](https://www.goodfire.com/research/mechanistic-shaping)

## The experiment that would justify shipping it

Use a paired 2×2 study. Every editor gets the same short inventory, public objective, public prompt-generation and behavioral scoring tools, writable tensor operations and submission semantics. Astra or Qwen may choose what to investigate. Both editors need their own paired comparisons. Keep the inspectable and writable target open-weight; the editor can be external.

| Arm | Public behavior checks | Internal intervention report | Reversible weight preview |
| --- | --- | --- | --- |
| A | Yes | No | No |
| B | Yes | Yes | No |
| C | Yes | No | Yes |
| D | Yes | Yes | Yes |

**D versus C is the primary comparison.** Both can try and reject candidate weight edits. Their difference tests whether access to internal evidence helps the editor find better permanent edits beyond behavioral feedback and reversible search. B versus A tests internal evidence under the current write policy. C versus A measures the value of preview alone. A stock IWIBench run is useful as an external reference. A matched non-informative measurement with comparable shape and target cost is an optional follow-up if internal evidence wins. Supply identical availability of writable neuron columns in C and D, so an easier write action cannot explain D’s apparent gain.

Use development tasks to choose the working feature count, output cap, reward effect worth shipping and an acceptable retention loss. Freeze those choices before the comparative test. For a descriptive pilot, draw two unused editing tasks in each of four deterministic families: remapping, alias acquisition, factual update and selective withholding. Two independent editor samples per task across four arms give **64 assigned attempts** for one editor. Interleave conditions and pair by task. All 15 official false-suggestion variants already have outcome data from our frozen-patch studies. Use them for development, or independently generate and qualify fresh variants before including that family in a confirmatory analysis. The public openings were previously measured for all 150 catalogue entries, so “unused” here refers to editing and grading outcomes. Keep hidden target items, evaluation prompts and their generators outside the editor process. Preserve no-submission outcomes. The A100 parity check above is the only new pretrained experiment for this research update.

Grade the unhooked submitted weights in a fresh process. Report official reward, signed fixes and regressions by slice, previously correct answers retained, and success/failure to submit. Use task-paired differences and uncertainty clustered by task. Track uncached and total editor tokens, target forwards/backwards, generation tokens, fit steps and elapsed time separately. Cap both sides’ opportunities to investigate and select a candidate. Ship whichever capability improves the prespecified quality/retention tradeoff at comparable cost. An increase in probe use or activation magnitude on its own would leave the product question unanswered.

If the eventual claim is continual learning or replacing agent memory, add a second experiment with a sequence of tasks and evaluate each saved patch on earlier tasks after every edit. Compare with the same unedited model given a matched retrieval-memory budget. Feature drift on public anchors is an auxiliary measurement. It cannot determine whether old tasks still work. [Feature-level continual-learning study](https://arxiv.org/abs/2606.26629)
