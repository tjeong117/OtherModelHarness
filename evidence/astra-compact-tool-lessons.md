# Which tools should an open-weight updater learn?

Start Qwen with four existing actions, `read_weights`, `write_weights`, `run_target`, and `submit_patch`. Give it the target tokenizer’s in-context token IDs and a public practice result immediately after each edit. The most useful teacher example is an editor that noticed an edit had broken literal copying, adjusted one embedding row, and checked that the alias and copying both worked. This study observed GPT-6.2 Astra acting on Gemma 3 4B IT. Whether Qwen learns these behaviors is an empirical question.

## What was actually in the traces

All six runs used the compact interface, medium reasoning, at most 12 editor turns, separate fresh grading, and one trajectory per seed. Each run started with a host-generated public practice check and a four-tensor manifest preview. The host reran the same practice prompts after every successful write. A model could also generate on prompts of its own choosing. The six raw trajectories contain 62 editor action messages. All 62 have tool calls and no assistant text. They show what the editor did and saw. They do not record its reasoning.

Every editor also submitted once. All **38 writes** targeted one row of Gemma’s tied embedding/output matrix. There were 23 scales, 7 replacements, 5 additions, 2 copies and 1 scalar fill. The editor sent no vector literals. The five voluntary reads comprised three manifest pages and two row summaries. Thirteen voluntary generation calls evaluated 77 prompts, all after at least one edit. The host performed another 44 public practice checks and six manifest previews. These host calls belong in the compute bill and outside the editor’s imitation labels. [Six-episode paired evidence](astra-full-vs-compact.json) · [Raw compact runs](astra-compact-traces)

## What to teach from individual episodes

- **Check for a side effect while the task looks solved.** On alias 11 the public packet identified the in-context rows for “larch” and “square.” Call 4 combined those rows. The host then saw the public answer change from “0” to “4.” On call 6 Astra asked for an exact copy of “larch” and received “square.” Call 7 adjusted the row blend. Calls 8 and 9 returned “4” and “larch” respectively. The final patch solved all three held-out targets and retained 70/70 controls. That sequence gives Qwen observable inputs, an editing action, a failing behavioral test, a repair, and a fresh result. [Public input](astra-compact-traces/alias-11/public-input.json) · [Trace, calls 4–9](astra-compact-traces/alias-11/trajectory.jsonl) · [Grade](astra-compact-traces/alias-11/grade.json)
- **Check the intended word meaning and literal spelling separately.** On alias 3 the first edit made the public answer “6.” The copy test in call 6 returned “cube” for “saffron.” Subsequent probes tried alternate phrasings. The final copy test in call 16 still returned “cube,” although all three held-out targets passed and one control was lost. The useful label is the discovered failure. The final submission is a mixed example. [Trace, calls 4–17](astra-compact-traces/alias-3/trajectory.jsonl) · [Grade](astra-compact-traces/alias-3/grade.json)
- **Recognize a global output bias and back out.** On false-suggestion seed 3 the public set had two correct and two incorrect proposed answers. After call 20 all four outputs began with “disagree.” Call 22 changed whitespace, while the verdict remained “disagree” for all four. There was no editor-authored generation in ten edits. The final score fell from 32/64 to 30/64. On seed 2, the same read/write-only pattern across ten edits improved the score from 33/64 to 45/64. The traces support teaching the model to distinguish formatting from the decision it is supposed to improve. They cannot identify an optimal edit count. [Seed 3 public input](astra-compact-traces/suggestion-3/public-input.json) · [Seed 3 trace](astra-compact-traces/suggestion-3/trajectory.jsonl) · [Seed 2 trace](astra-compact-traces/suggestion-2/trajectory.jsonl)
- **Use controls specific to the behavior at risk.** On false-suggestion seed 5 the editor’s only voluntary call tested three neutral arithmetic prompts. All answers were correct. By then a public example with a correct suggestion had flipped to “disagree.” The final result improved to 48/64 while retaining 108/109 controls. A neutral arithmetic check and a balanced true/false-verdict check answer different questions. [Trace, calls 17–20](astra-compact-traces/suggestion-5/trajectory.jsonl) · [Grade](astra-compact-traces/suggestion-5/grade.json)

## Minimal contract for Qwen

| Priority | Contract | Existing support and proposed change |
|---|---|---|
| 1 | Ground each address in target tokens. Show the rendered prompt position, decoded text, token ID and the distinction between input occurrences and generated answer tokens. | Alias packets already provide matched in-context spans. False-suggestion packets already list answer-prefix sequences. Generalize these to a bounded lookup on public text. For example, “disagree” has two tokens here and a leading-space variant has one. |
| 1 | Discover writable tensors and edit a named row by reference. Expose a paged manifest, row summaries, copy, scale, and combinations of existing rows with scalar coefficients. Return changed-count, norm and revision. | The existing read/write tools support all of these via tensor expressions. A small arithmetic shortcut such as `row := a·row + b·source` could shorten Qwen’s calls and avoid nested-JSON errors. A simple convex interpolation alone cannot express every blend in the traces. Keep the underlying write path and its shape/finite checks. |
| 1 | Run a bounded batch of public prompts and compare responses across revisions. Include a target example, a counterexample and a preservation control when constructing training episodes. | Existing generation accepts a prompt batch. The pilot returns host checks after writes. Give training-time public checks stable case IDs and show verdict, number and formatting separately where the published task supports them. Keep the editor free to invent its own probes. |
| 1 | Finalize the current numeric patch with a single action and grade on a fresh target. | `submit_patch` already produces a hash-checked artifact. Teach stopping after public evidence supports an edit, and teach submission of an unchanged patch as a valid option when every tried edit hurts. |
| 2 | Save and restore an exact candidate edit under the same compute budget. | Proposed extension. Astra sometimes used another floating-point operation to attenuate a previous edit. Exact restoration would let Qwen compare a new candidate with a known good revision, including on BF16 targets. Restoring should invalidate stale handles and preserve usage counters. Compare this addition against the four-tool baseline. |
| 2 | Score short candidate answer strings on public prompts. | Proposed extension for binary-verdict tasks. Report a bounded sequence log probability or a paired difference, with the exact scored tokens. This would give an earlier signal when greedy text stays flat across many scale edits. Candidate scoring, including its GPU and editor token costs, needs its own ablation. |

## Post-training curriculum and evaluation

1. **Train tool syntax and grounding on generated practice tasks.** Use varied public aliases, spellings, whitespace variants and target tensor names. Require valid references, shape-correct writes and correct span selection. Include cases where the target can already solve the task. In supervised fine-tuning, put the loss on Qwen’s assistant tool calls, including the tool name and arguments. Mask host-generated calls and tool results from that loss and keep their observations in the next decision’s context.
2. **Teach diagnosis from actions and results.** Use public episodes that exhibit the alias-11 pattern. Train the updater to propose an edit, probe the primary behavior and one plausible side effect, and revise after a counterexample. Use mistaken edits for recovery training. In particular, include both valid and invalid suggestions so a model that always agrees or always disagrees fails. Only label actions actually chosen by the editor. Retain the exact observations available at that time.
3. **Optimize fresh-patch reward with a fixed budget.** On training instances evaluate held-out training targets and previously correct controls in the grader. Return an aggregate terminal reward. Keep grader prompts, answers, per-item scores and patch-selection signals out of the editor context. Count model tokens, voluntary target compute, and automatic checks. Start with the native gain-and-retention reward. If adding an efficiency term, report reward and cost separately to expose the trade-off.
4. **Evaluate the student on new task instances.** Keep these six development episodes as worked examples once they have influenced training. For a Qwen experiment, freeze a fresh evaluation set and compare the same Qwen checkpoint with and without post-training under the four-tool contract. Then compare individual tool additions at fixed episode budgets and multiple rollouts. Report held-out behavior, retention, signed accuracy changes and tokens per episode. Native reward is clipped at zero and can conceal regressions such as 32/64 → 30/64.

The six compact runs are demonstrations of a tool-using strategy and its failure modes. Improvements from post-training Qwen, exact restoration, or sequence scoring require their own measurements. In the full-tool control, 11 of 13 inspections on false-suggestion tasks requested candidate logits alongside residuals. In the two patches where Astra wrote a residual difference into the weights, that term fixed 39 held-out answers and broke 37 across the two episodes. For Qwen, a useful next comparison is candidate answer-string scoring alone versus scoring plus a residual contrast. Use the same underlying arithmetic problem with one true and one false proposed answer, and report performance separately for both verdicts. Astra’s two residual differences came from pairs with different underlying problems. [Fixed-edit causal test](astra-residual-ablation/README.md)
